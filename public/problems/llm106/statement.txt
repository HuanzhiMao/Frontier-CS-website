BIPARTITE VERIFICATION
======================

INTERACTIVE PROBLEM

PROBLEM DESCRIPTION
-------------------
Bob has a simple undirected connected graph (without self-loops and multiple edges). He wants to learn whether his graph is bipartite (that is, you can paint all vertices of the graph into two colors so that there is no edge connecting two vertices of the same color) or not.

Bob doesn't want to disclose his graph to Alice, but he agreed that Alice can ask him questions about the graph. The only question Alice can ask is: she sends s (a subset of vertices of the original graph), and Bob answers with the number of edges that have both endpoints in s.

Since Bob doesn't want Alice to learn too much about the graph, he allows her to ask no more than 50000 questions.

Furthermore, Bob suspects that Alice might introduce false messages to their communication channel. When Alice finally tells him whether the graph is bipartite or not, she also needs to provide a proof:
  - If bipartite: the partitions themselves
  - If not bipartite: a cycle of odd length

Your task is to help Alice construct the queries and find whether the graph is bipartite.

SCORING
-------
Let q be the number of queries you asked. Your score will be:

    Score = (5000 - q) / 5000

INTERACTION PROTOCOL
--------------------
1. First, read integer n (1 ≤ n ≤ 600): the number of vertices in Bob's graph

2. To make a query:
   - Print two lines
   - First line: "? k" (1 ≤ k ≤ n), where k is the size of the set to be queried
   - Second line: k space-separated distinct integers s_1, s_2, ..., s_k (1 ≤ s_i ≤ n)

3. After each query:
   - Read integer m (0 ≤ m ≤ n(n-1)/2): number of edges between vertices in {s_i}
   - If m = -1: you asked too many queries or an invalid query; terminate immediately

4. After printing a query:
   - Print end of line and flush the output
   - C++: fflush(stdout) or cout.flush()
   - Java: System.out.flush()
   - Pascal: flush(output)
   - Python: stdout.flush()

5. When you know the answer:
   - If bipartite: print "Y s" followed by s integers a_1, a_2, ..., a_s (vertices in first partition)
     All a_i must be distinct, and all edges must have exactly one endpoint in {a_i}
   - If not bipartite: print "N l" followed by l integers c_1, c_2, ..., c_l (vertices along odd cycle)
     For all 1 ≤ i ≤ l, there must be an edge {c_i, c_{(i mod l)+1}}, and all c_i must be distinct

CONSTRAINTS
-----------
  - 1 ≤ n ≤ 600
  - Maximum 50000 queries allowed

EXAMPLES
--------
Example 1

Input:
4
4
0
1
1
1
0

Output:
? 4
1 2 3 4
? 2
1 2
? 2
1 3
? 2
1 4
? 2
2 4
? 2
3 4
Y 2
1 2

Note: Alice learns there are 4 edges in the graph. She discovers vertex 1 has neighbors 3 and 4, vertex 2 is adjacent to 4, but vertex 3 is not adjacent to 4. The only option for the remaining edge is (2,3). This is a cycle on four vertices, with partition (1,2) and (3,4).

--------
Example 2

Input:
4
4
3

Output:
? 4
1 4 2 3
? 3
1 2 4
N 3
2 1 4

Note: Alice learns there are three edges among vertices (1,2,4). The only way this can happen is if they form a triangle. As a triangle is not bipartite, Alice reports it as proof.
